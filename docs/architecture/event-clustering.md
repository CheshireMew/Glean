# 事件聚合

Glean 不再把相似报道分成“主新闻”和“重复新闻”。每家媒体的原始报道都保存在 `news`，跨来源事件保存在 `content_events`，两者通过 `event_sources` 建立可追溯关系。

## 处理过程

1. 抓取器将来源条目写入 `news.stage = incoming`。
2. `EventClusterer` 对标题做同义词、数字、英文实体和中文二元/三元片段归一化。
3. 在配置的时间窗口内计算序列、词元、实体和数字相似度，并用连通分量形成事件候选组。
4. 每组选择正文信息最完整的来源作为规范来源，但其他来源不会被删除。
5. 新组会生成 `content_events`；后来出现的报道可以加入已有事件。
6. 全部成员写入 `event_sources`，原始来源统一进入 `news.stage = archived`。

事件匹配阈值存放在 `automation.event.threshold`。后台“事件聚合”页面可以查看规范来源、其他来源及各自匹配度。移除规范来源时，系统会从剩余来源中重新选出规范来源，并同步归档和审核记录。

## 与日报的关系

审核、补充和日报处理的对象是事件，不是单篇转载。多来源事件会保留各自链接，并在排序中获得有限的交叉印证加权；最终日报仍受栏目和来源配额约束。
